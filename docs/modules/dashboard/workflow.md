# Dashboard — Workflow

> Status: **Approved (2026-08-03)** — حسم المالك، **DEC-DSH-013**.
> **اللوحة لا تحمل مسار عمل خاصًّا بها** — لا حالة، ولا آلة حالات، ولا معاملة
> (BR-DSH-001، BR-DSH-020). المسارات أدناه هي **مسارات قراءة وتنقّل**: كيف
> تُقرأ اللوحة، وكيف تُسلِّم المستخدم إلى الوحدة التي تملك الفعل.

---

## 1 · المسار الأساسي — صباح المالك (الثلاثون ثانية)

```
تسجيل الدخول
    ↓
لوحة التشغيل  (وجهة الهبوط — DEC-DSH-011)
    ↓
طلب واحد:  GET /api/v1/dashboard        (REQ-DSH-010)
    ↓
هيكل عظميّ لكلّ قسم فورًا، ثم تُملأ الأقسام   (BR-DSH-019)
    ↓
┌─ «ما يحتاج انتباهك» خالٍ؟ ──────────────────────────┐
│  نعم → حالة اطمئنان واحدة (BR-DSH-013)  →  يمضي     │
│  لا  → يمسح البنود بترتيبها الثابت (BR-DSH-012)     │
│         ↓                                            │
│       ينقر البند الأخطر                              │
│         ↓                                            │
│       الشاشة الوجهة **مفلترة على البند نفسه**        │
│         (BR-DSH-018 — الفلتر من قائمة بيضاء معتمدة)  │
│         ↓                                            │
│       **الفعل يجري هناك، في وحدته** (BR-DSH-020)     │
└──────────────────────────────────────────────────────┘
```

**النقطة الجوهرية في هذا المسار:** اللوحة **تنتهي عند التسليم**. لا تعالج، ولا
تصحّح، ولا تُثبت — **تدلّ ثمّ تنسحب**. الفعل كلّه يجري في الوحدة المالكة، بقواعدها
وشاشاتها وبواباتها القائمة.

## 2 · مسارات التسليم — من البند إلى الفعل

| البند | الوجهة (مفلترة) | الفعل الذي يجري هناك، في وحدته |
|---|---|---|
| **منتهية الصلاحية** | `/inventory/expiry` · «منتهية» | **إهلاك** الدفعة — `/inventory/write-offs/new` (REQ-INV-011) |
| **نفاد المخزون** | `/inventory` · «نفاد المخزون» | **فاتورة شراء جديدة** — `/purchases/new` (REQ-PUR-003) |
| **تقارب الانتهاء** | `/inventory/expiry` · «قرب الانتهاء» | تصريفٌ بالبيع، أو منعُ شراءٍ إضافيّ — قرار عمل لا شاشة |
| **فواتير شراء مسودة** | `/purchases` · «مسودة» | **الاستلام** — `/purchases/:id` (REQ-PUR-005) |
| **فواتير بيع مسودة** | `/sales` · «مسودة» | **إثبات البيع** — `/sales/:id` (REQ-SAL-003) |
| **مبيعات اليوم** | `/sales` · مدى تاريخ اليوم | مراجعة · فتح فاتورة · **مرتجع بيع** (REQ-SAL-004) |
| **آخر الحركات** | `/inventory/history` | فحص · وعند الخطأ **حركة عكسية** (DEC-INV-037) |
| **بيع جديد** | `/sales/new` | إنشاء فاتورة بيع (REQ-SAL-001) |
| **فاتورة شراء جديدة** | `/purchases/new` | إنشاء فاتورة شراء (REQ-PUR-003) |
| **منتج جديد** | `/catalog/products/new` | إنشاء منتج (Catalog) |

> **كلّ وجهة في هذا الجدول مسارٌ قائم ومُنفَّذ اليوم.** ما **ليس** قائمًا هو
> **قراءة الفلتر من عنوان الرابط** — لا شاشة ميزة واحدة تفعل ذلك بعد
> (**DEC-DSH-006**). تبعة تنفيذ **إضافية**، **بلا تعديل قاعدة**، لأنّ كلّ فلتر
> مطلوب **قائم سلفًا في قائمة بيضاء معتمدة**.

## 3 · مسار الجلب — طلب واحد، أقسام تفشل مستقلّةً

```
GET /api/v1/dashboard   ← طلب واحد لا ثمانية (REQ-DSH-010)
    │
    ├─ الأقسام تُجلب في مسار واحد، بلا N+1 ولا تحميل كسول (BR-DSH-019)
    │
    └─ الردّ:  لكلّ قسم  { نجاح + بيانات }  أو  { فشل }
                     ↓                          ↓
              يُعرض محتواه            «تعذّر الجلب» + إعادة المحاولة
                                       **داخل بطاقته وحدها**
                                       ⛔ ولا يُعرض صفرًا أبدًا
                                          (BR-DSH-014)
```

**لماذا هذا الشكل بالذات:** التكليف طلب **نقطة نهاية واحدة** وطلب **حالات إعادة
محاولة** — ولا يجتمعان إن كان الردّ يفشل ككتلة. والحلّ **ليس اجتهادًا**: في إبِك
«Pilot UX Polish» (2026-08-02) صُمّمت بطاقة مخزون المنتج لتُحمَّل مستقلّةً حتى
«يُظهر تعطّلُ المخزون إعادةَ محاولة في بطاقة واحدة بدل أن يُفرِّغ صفحةً حُمِّلت خمسُ
بطاقاتها». **لوحةٌ من ثمانية أقسام تسقط كلّها لتأخّر المشتريات تعيد الخطأ نفسه
بحجم أكبر** (**DEC-DSH-002**).

## 4 · مسار التحديث

- **لا تحديث تلقائيّ، ولا استقصاء، ولا دفع** (**BR-DSH-015**، **DEC-DSH-010**).
- التحديث **بطلب صريح** من المستخدم، ويُعيد **جلب اللوحة** لا بناء الصفحة.
- **إعادة محاولة قسم فاشل تُعيد قسمه وحده** — لا اللوحة (**§9**: «لا يُطلب من
  المستخدم أن يعيد عملًا لم يخطئ فيه»).
- **الرجوع من وجهة إلى اللوحة** يُعيد قراءتها — وهذا مقصود: المستخدم غالبًا
  **عالج شيئًا للتوّ**، فرؤية الرقم وقد نقص **هي تأكيد الفعل** (**§9**: «كلّ فعل
  له نتيجة مرئية»).

## 5 · مسارات الاستثناء

| الاستثناء | السلوك |
|---|---|
| **فشل قسم واحد** | خطأ + إعادة محاولة **في بطاقته**؛ بقيّة اللوحة تعمل (BR-DSH-014) |
| **فشل كلّ الأقسام** | خطأ عامّ **بلغة عمل**، بلا شيفرات تقنية، مع إعادة محاولة |
| **انتهاء الجلسة أثناء العرض** | يُعالَج بمسار الهُويّة القائم — **عودة مرئية إلى `/login`** (DEC-IDN-016). **اللوحة لا تخترع مسارًا ثانيًا** |
| **زائر غير مُصادَق** | لا يصل إلى اللوحة ولا إلى قراءتها (REQ-IDN-006) |
| **بطء قسم** | هيكله العظميّ يبقى؛ **ولا تُحجَب الأقسام الجاهزة بانتظاره** (BR-DSH-019) |

## 6 · ما لا يوجد في هذه الوحدة — عمدًا

- **لا آلة حالات ولا حالة مستمرّة** — اللوحة عديمة الحالة (BR-DSH-001).
- **لا معاملة ولا كتابة ولا تزامن** — لا تكتب شيئًا، فلا تعارض تُكشفه.
- **لا نموذج ولا تحقّق مدخلات** — لا مدخل للمستخدم أصلًا.
- **لا مسار تصعيد ولا إشعار ولا مهمّة خلفية** — **BR-INV-032** تمنعها،
  و**Monitoring** وحدة مؤجَّلة (**DEC-INV-017**).
