# Identity — Workflow

> Status: **Approved** — owner ruling 2026-08-02.
> Authority: ADR-0022 §7.

## مسار الدخول

```
شاشة الدخول
      ↓
رقم الهاتف + كلمة المرور
      ↓
يُبحَث عن المستخدم برقم الهاتف
      ↓
تُقارَن كلمة المرور بالمُجزَّأة المخزَّنة
      ↓
تُقرأ عضويته (المنشأة + الدور) ويُحدَّد فرعه
      ↓
يُصدَر رمز وصول يحمل: المستخدم · المنشأة · الفرع · الدور
      ↓
ينتقل المستخدم إلى الشاشة الأولى (قائمة المنتجات)
```

> **⚠ مَنسوخ (2026-08-02):** الشاشة الأولى تصير **لوحة التشغيل**
> (`../dashboard/` — **DEC-DSH-011**) **عند تنفيذها**؛ وهي اليوم Draft غير
> منفَّذة، فالمخطَّط أعلاه يصف الواقع القائم. **خطوات المصادقة نفسها لا تتغيّر.**

**أيّ فشل في أيّ خطوة** — رقم غير موجود · كلمة مرور خاطئة · لا عضوية —
**يُعرَض برسالة واحدة موحّدة** (BR-IDN-003).

## مسار كلّ طلب بعد الدخول

```
الطلب يحمل الرمز
      ↓
يُتحقَّق من التوقيع ومن الصلاحية
      ↓
تُبنى هويّة الطلب من المطالبات
      ↓
يُبنى سياق المنشأة والفرع  ← من المطالبات حصرًا (BR-IDN-004)
      ↓
تُرشَّح القراءة وتُوسَم الكتابة تلقائيًّا (BR-ORG-003)
```

## مسار انتهاء الجلسة

```
رمز منتهٍ أو مرفوض
      ↓
يُرفض الطلب
      ↓
يُعاد المستخدم إلى شاشة الدخول برسالة تُفسِّر ما حدث   ← لا فشل صامت (BR-IDN-008)
```

## مسار الخروج

```
المستخدم يطلب الخروج
      ↓
يُتخلَّص من الرمز على العميل
      ↓
شاشة الدخول
```

## ما لا يحدث

لا تسجيل ذاتيّ · لا دعوة · لا استرجاع كلمة مرور · لا تجديد تلقائيّ للرمز ·
لا اختيار منشأة أو فرع.
