# Purchasing — Test Scenarios

> Status: Approved (2026-07-16) — Slice 1 (Purchase List); Approved (2026-07-17) — Slice 2 (Purchase Details); Approved (2026-07-17) — Slice 3 (Create Purchase); Approved (2026-07-17) — Slice 4 (Purchase Line Items): TS-PUR-016..024; **Approved (2026-07-22) — Slice 5 (Purchase Receiving): TS-PUR-025..033 — DoR مكتملة.** Sprint 4.

### TS-PUR-001 — عرض القائمة مع بيانات
معطى فواتير شراء موجودة، عند فتح الشاشة تُعرض بالأعمدة الستة (رقم النظام، المورد، تاريخ الفاتورة،
الحالة، الإجمالي، تاريخ الإنشاء) وأحدث فاتورة أولًا. (REQ-PUR-001، BR-PUR-004)

### TS-PUR-002 — الحالة الفارغة
معطى لا فواتير، تُعرض حالة «فارغ». (REQ-PUR-001)

### TS-PUR-003 — البحث باسم المورد (تطبيع عربي)
البحث بجزء من اسم المورد يُرجِع الفواتير المطابقة بعد التطبيع العربي. (BR-PUR-004)

### TS-PUR-004 — فلتر الحالة
تحديد «مسودة» يقصر النتائج على المسودات. (BR-PUR-004)

### TS-PUR-005 — الفرز والترقيم المستقر
الفرز بالتاريخ/الإجمالي مع مُكسِّر تعادل ثابت (المعرّف) وترقيم مستقر عبر الصفحات. (BR-PUR-004)

### TS-PUR-006 — شارة الحالة العربية
كل صف يعرض شارة الحالة الصحيحة: مسودة / مستلمة / ملغاة. (AC-PUR-002)

### TS-PUR-007 — تنسيق رقم النظام
يُعرض رقم النظام بالصيغة `PUR-000001`. (AC-PUR-003)

## Slice 2 — Purchase Details

### TS-PUR-008 — عرض التفاصيل مع بيانات
معطى فاتورة موجودة، عند فتح تفاصيلها تُعرض ترويستها كاملةً للقراءة فقط (شارة الحالة، رقم النظام،
اسم المورد، مرجع فاتورة المورد، تاريخ الفاتورة، الإجمالي، الملاحظات، تاريخ الإنشاء). (REQ-PUR-002، AC-PUR-004)

### TS-PUR-009 — فاتورة غير موجودة
معطى معرّف فاتورة لا يوجد، تُعرض حالة «غير موجود». (REQ-PUR-002، AC-PUR-005)

### TS-PUR-010 — الحقول الاختيارية
حين يغيب مرجع فاتورة المورد أو الملاحظات، تتصرّف الشاشة بلا خطأ (تُخفى القيمة أو يظهر بديل)؛ وحين
توجد تُعرض كما هي. (REQ-PUR-002، BR-PUR-001)

### TS-PUR-011 — شارة الحالة ورقم النظام في التفاصيل
تُعرض شارة الحالة الصحيحة (مسودة/مستلمة/ملغاة) ورقم النظام بالصيغة `PUR-000001` في شاشة التفاصيل.
(AC-PUR-002، AC-PUR-003)

## Slice 3 — Create Purchase

### TS-PUR-012 — إنشاء ناجح
معطى اسم مورد وتاريخ فاتورة صحيحين، عند الحفظ تُنشأ فاتورة **مسودة** برقم `PUR-` مُولَّد وإجمالي صفر،
وينتقل المستخدم إلى شاشة تفاصيلها. (REQ-PUR-003، AC-PUR-006)

### TS-PUR-013 — الحقول المطلوبة
حذف اسم المورد أو تاريخ الفاتورة يمنع الحفظ ويُظهر خطأً **حقلًا بحقل**، دون إنشاء أيّ فاتورة. (REQ-PUR-003، AC-PUR-007)

### TS-PUR-014 — الحقول الاختيارية
يُسمح بالحفظ بدون مرجع المورد وبدون ملاحظات؛ وحين تُدخَل تُحفظ كما هي (تُقصّ المسافات، والفارغ يُعامَل كغياب). (REQ-PUR-003، BR-PUR-001)

### TS-PUR-015 — الرقم والحالة يُولَّدان آليًا
رقم النظام يُولَّد بالصيغة `PUR-000001` عند الحفظ (تسلسل تصاعدي فريد)، والحالة الابتدائية **مسودة** دائمًا
— لا يختارهما المستخدم. (BR-PUR-002، BR-PUR-003)

## Slice 4 — Purchase Line Items

### TS-PUR-016 — إضافة بند
معطى فاتورة **مسودة**، إضافة بند (منتج + وحدة شراء + كمية + سعر وحدة) يُنشئ بندًا بإجمالي = الكمية × سعر
الوحدة، ويحدّث إجمالي الفاتورة. (REQ-PUR-004، AC-PUR-008)

### TS-PUR-017 — اشتقاق إجمالي الفاتورة من البنود
معطى بندان بإجماليات مختلفة، إجمالي الفاتورة = **مجموعهما** (مشتق، لا مُدخَل). (BR-PUR-006، AC-PUR-008)

### TS-PUR-018 — تحقّق الكمية وسعر الوحدة حقلًا بحقل
كمية = 0 أو سالبة، أو سعر وحدة سالب، أو غياب منتج/وحدة → **رفض حقلًا بحقل** دون إضافة البند ودون تغيير
الإجمالي. (BR-PUR-005، AC-PUR-009)

### TS-PUR-019 — حذف بند يعيد حساب الإجمالي
معطى بندان، حذف أحدهما يترك إجمالي الفاتورة = إجمالي البند المتبقّي؛ حذف الأخير يجعل الإجمالي **صفرًا**.
(BR-PUR-006، AC-PUR-010)

### TS-PUR-020 — وحدة الشراء من وحدات الشراء فقط
قائمة الوحدات القابلة للاختيار عند إضافة بند = **وحدات الشراء** للمنتج (`IsPurchaseUnit`)، والافتراضية
**وحدة الشراء الافتراضية** للمنتج. (BR-PUR-005، DEC-PUR-003)

### TS-PUR-021 — لقطة اسم المنتج/الوحدة
بعد إضافة بند، يظل **اسم المنتج واسم الوحدة** على البند كما كانا وقت الإضافة، ولا يتأثران بتغيّر بيانات
الكتالوج لاحقًا (وثيقة تاريخية). (BR-PUR-005، DEC-PUR-003)

### TS-PUR-022 — التغيير للمسودات فقط
محاولة إضافة/حذف بند لفاتورة **مستلمة/ملغاة** تُرفض؛ المسودة فقط تقبل التغيير. (BR-PUR-005، AC-PUR-012)

### TS-PUR-023 — عرض البنود في التفاصيل
تعرض شاشة التفاصيل قسم البنود بالأعمدة الخمسة (المنتج · وحدة الشراء · الكمية · سعر الوحدة · إجمالي البند)
أسفل الترويسة، وإجمالي الفاتورة يطابق مجموع البنود. (REQ-PUR-004، AC-PUR-011)

### TS-PUR-024 — ثبات لقطة اسم المنتج بعد إعادة التسمية في الكتالوج
1. إنشاء فاتورة شراء. 2. إضافة بند شراء (منتج). 3. إعادة تسمية المنتج في الكتالوج. 4. فتح تفاصيل الفاتورة.
5. التحقّق من أن **اسم المنتج الأصلي** ما زال معروضًا على البند (لقطة تاريخية ثابتة). (AC-PUR-013، BR-PUR-007)

## Slice 5 — Purchase Receiving (Approved 2026-07-22)

### TS-PUR-025 — استلام مسودة بها بنود
معطى فاتورة **مسودة** بها بند واحد أو أكثر، عند تأكيد الاستلام تنتقل إلى **مستلمة**، وتُنشأ دفعة لكل بند،
وتزداد كميات المخزون؛ وتُعرض شارة «مستلمة». (REQ-PUR-005، AC-PUR-014)

### TS-PUR-026 — لا استلام مرتين
معطى فاتورة **مستلمة**، محاولة استلامها ثانيةً **تُرفض دون أثر**. (BR-PUR-009، AC-PUR-015)

### TS-PUR-027 — لا استلام فاتورة بلا بنود
معطى فاتورة **مسودة بلا بنود**، محاولة الاستلام **تُرفض دون أثر**. (BR-PUR-009، AC-PUR-016)

### TS-PUR-028 — لا استلام فاتورة ملغاة
معطى فاتورة **ملغاة**، محاولة الاستلام **تُرفض** (الحالة نهائية، BR-PUR-003). (BR-PUR-012، AC-PUR-015)

### TS-PUR-029 — الفاتورة المستلمة ثابتة
معطى فاتورة **مستلمة**، محاولة إضافة/حذف/تعديل بند أو تحرير الترويسة **تُرفض**. (BR-PUR-011، AC-PUR-017)

### TS-PUR-030 — دفعة واحدة لكل بند
معطى فاتورة مسودة بها بندان، بعد الاستلام تنشأ **دفعتان** (دفعة لكل بند) في النسخة الأولى. (BR-PUR-010)

### TS-PUR-031 — الصلاحية عند الاستلام حسب تعريف المنتج
منتجٌ **يُلزِم الصلاحية** وغابت صلاحية بنده → **يُرفض الاستلام**؛ منتجٌ يُلزِمها وأُدخِلت → دفعة **تحمل الصلاحية**؛
منتجٌ **لا يُلزِمها** → دفعة **بلا تاريخ صلاحية**. (BR-PUR-013، BR-PUR-012، AC-PUR-018)

### TS-PUR-032 — ذرّية الاستلام
معطى فشل أثناء إنشاء المخزون، **لا يتغيّر شيء**: تبقى الفاتورة **مسودة** ولا تُنشأ دفعات ولا تتغيّر كميات
(كلّه أو لا شيء). (BR-PUR-010)

### TS-PUR-033 — العقد العام للدفعة (Batch)
بعد استلام فاتورة، **كل دفعة ناتجة**: (١) تناظر **بندًا واحدًا** (بند ↔ دفعة)، (٢) **تشير إلى بند الشراء** المُنشِئ
لها، (٣) تخزّن **المنتج والكمية وتكلفة الوحدة** (= سعر وحدة البند) **وصلاحية اختيارية**. تنفيذ المخزون مملوك
لوحدة Inventory. (BR-PUR-010، DEC-PUR-008)

## مرتجع المشتريات (Epic 2 · C5) — TS-PUR-034..041

### TS-PUR-034 — إنشاء مسودة مرتجع لفاتورة مستلَمة
بمعطى فاتورة مستلَمة، يُنشأ مرتجع **مسودة** برقم `PRT-` فريد ومورّد مطابق للفاتورة الأصليّة. (AC-PUR-019)

### TS-PUR-035 — رفض المرتجع مقابل فاتورة مسودة أو ملغاة
محاولة إنشاء مرتجع لفاتورة **مسودة**، ثم لفاتورة **ملغاة** → **مرفوضة دون أثر** في الحالتين. (AC-PUR-020)

### TS-PUR-036 — إرجاع جزئيّ يُقبل ويُنقص المتبقّي
بند أصليّ كمّيته ١٠ → إرجاع ٣ **مثبَّت** → المتبقّي القابل للإرجاع **٧**. (AC-PUR-021)

### TS-PUR-037 — تجاوز المتبقّي مرفوض دون أثر
بعد إرجاع ٧ من أصل ١٠ (مثبَّت)، محاولة إرجاع ٤ → **مرفوضة**، ولا يُكتب سطر في سجلّ الحركة ولا تتغيّر
أيّ كمّية. (AC-PUR-022)

### TS-PUR-038 — المرتجع المسودة لا يحجز كمّية
مرتجع **مسودة** بكمّية ٥ لا يُنقص المتبقّي القابل للإرجاع؛ مرتجع آخر بالكمّية الكاملة **يُقبل**. (AC-PUR-022)

### TS-PUR-039 — التثبيت يحرّك الكمّيتين معًا ويكتب سطرًا واحدًا
بعد التثبيت: `remaining_quantity` للدفعة و`on_hand_quantity` للمنتج **ينقصان بنفس القيمة**
(BR-INV-005 يبقى محفوظًا)، ومعهما **سطر واحد** نوعه `PurchaseReturn`. (AC-PUR-023)

### TS-PUR-040 — الإرجاع يتجاهل FEFO ويلتزم دفعة المصدر
بمعطى منتج له دفعتان — دفعة المصدر تنتهي **لاحقًا** وأخرى تنتهي **قريبًا** — الإرجاع يخرج **من دفعة
المصدر** لا من الأقرب انتهاءً. (AC-PUR-024)

### TS-PUR-041 — ثبات المستند بعد التثبيت
بعد التثبيت: تحرير الترويسة · إضافة بند · حذف بند · تثبيت ثانٍ · إلغاء → **كلّها مرفوضة دون أثر**.
(AC-PUR-025)
