> يلتزم بلغة التصميم المعتمدة و`docs/ui/` — RTL، خصائص CSS منطقية، مكوّنات VetFlow UI Kit فقط.

## شاشة قائمة المشتريات

- **العنوان:** «المشتريات».
- **الأعمدة (مجمّدة):** رقم النظام · المورد · تاريخ الفاتورة · الحالة (شارة) · الإجمالي (EGP) ·
  تاريخ الإنشاء. لا أعمدة إضافية (BR-PUR-004).
- **مرجع فاتورة المورد (عرض فقط، ليس عمودًا):** حين يوجد، يُعرض **سطرًا ثانويًا صغيرًا أسفل اسم المورد**
  داخل خانة «المورد» (بادئة «مرجع المورد:») — على نمط السطر الثانوي في قائمة المنتجات (الحجم/التركيز).
  ليس عمودًا سابعًا؛ حقلٌ معتمد يدخل البحث (BR-PUR-001، BR-PUR-004). يبقى العدّ ستة أعمدة.
- **البحث:** حقل بحث واحد — «ابحث برقم الفاتورة أو اسم المورد أو مرجع المورد…» (رقم النظام /
  اسم المورد / مرجع فاتورة المورد **فقط** — لا يشمل الملاحظات، BR-PUR-004).
- **الفلاتر:** الحالة (مسودة/مستلمة/ملغاة)، ومدى تاريخ الفاتورة (من/إلى) — لا غير.
- **الفرز:** رقم النظام · تاريخ الفاتورة · المورد · الحالة · الإجمالي.
- **شارات الحالة (دلالة فقط — الألوان تخصّ لغة التصميم، لا تُعرَّف هنا):**
  - مسودة → **محايد (Neutral)**
  - مستلمة → **نجاح (Success)**
  - ملغاة → **خطر (Danger)**
- **الحالات الأربع للعرض:**
  - **تحميل** → هيكل (`VfSkeleton`).
  - **فارغ** → النص: «لا توجد فواتير شراء حتى الآن»، مع زرّ رئيسي: «إنشاء فاتورة شراء».
    **مُفعَّل من الشريحة 3** — ينتقل إلى شاشة إنشاء فاتورة الشراء (`/purchases/new`).
  - **خطأ** → رسالة خطأ مع إعادة المحاولة.
  - **بيانات** → الجدول (سطح المكتب) / البطاقات (الجوال).
- **الاستجابة:** جدول (`VfTable`) على سطح المكتب، وبطاقات على الجوال — نمط قائمة المنتجات المعتمد.
- **زرّ الإنشاء (من الشريحة 3):** زرّ رئيسي «إنشاء فاتورة شراء» في ترويسة الشاشة (نمط زرّ «منتج جديد» في
  قائمة المنتجات) ينتقل إلى `/purchases/new`.

## شاشة إنشاء فاتورة الشراء (Slice 3)

- **الغرض:** إنشاء **ترويسة** فاتورة شراء جديدة فقط — على نمط **إنشاء المنتج المعتمد** (نفس تخطيط النموذج،
  نفس تجربة التحقق، نفس مكوّنات Vf للحقول). أول مسار كتابة في وحدة المشتريات.
- **العنوان:** «إنشاء فاتورة شراء».
- **الحقول (بالترتيب):**
  1. **اسم المورد** — نصّي، **مطلوب** (`VfTextInput`).
  2. **مرجع فاتورة المورد** — نصّي، **اختياري** (`VfTextInput`).
  3. **تاريخ الفاتورة** — تاريخ، **مطلوب** (`VfDateInput`).
  4. **الملاحظات** — نص متعدّد الأسطر، **اختياري** (`VfTextarea`).
- **بلا اختيار للحالة ولا لرقم النظام:** الحالة الابتدائية **مسودة** دائمًا، ورقم النظام يُولَّد آليًا عند
  الحفظ (BR-PUR-002/003) — لا يظهران كحقلين قابلين للإدخال.
- **بلا بنود/إجمالي في هذه الشريحة:** لا جدول أصناف ولا حقل إجمالي (الإجمالي صفر حتى شريحة البنود).
- **الإجراءات:** «حفظ» (إنشاء) و«إلغاء» (رجوع إلى القائمة دون إنشاء).
- **التحقق (تجربة الإنشاء المعتمدة):** رسائل خطأ **حقلًا بحقل** عربية RTL عند غياب اسم المورد أو تاريخ
  الفاتورة (AC-PUR-007)؛ لا تُنشأ فاتورة عند الفشل.
- **النجاح:** بعد الحفظ ينتقل المستخدم إلى **تفاصيل الفاتورة** المُنشأة (`/purchases/:id`) — REQ-PUR-002.
- **الاستجابة:** نموذج متجاوب دون فيض أفقي على سطح المكتب والجوال؛ RTL؛ خصائص CSS منطقية فقط.
- **المسار:** `/purchases/new` (يُسجَّل قبل `/purchases/:id`).

## شاشة تفاصيل فاتورة الشراء (Slice 2)

- **الغرض:** يفتحها المستخدم من صفٍّ في القائمة ليطالع ترويسة الفاتورة كاملةً **للقراءة فقط** —
  على نمط **تفاصيل المنتج المعتمد** (نفس تخطيط الصفحة، نفس أنماط العرض، نفس مكوّنات Vf).
- **العنوان (مُصغَّر — حسم المالك 2026-07-17):** عنصران فقط — **رقم النظام** (`PUR-000001`) مع **شارة
  الحالة** بجواره (مسودة/مستلمة/ملغاة — دلالة الألوان من لغة التصميم). **لا يُضاف اسم المورد ولا أيّ
  بيانات أخرى إلى العنوان؛** المورد يظهر داخل قسم المعلومات فقط.
- **الترتيب القانوني المُجمَّد للتفاصيل (حسم المالك 2026-07-17 — لا يُعاد ترتيبه دون قرار UX معتمد):**
  1. رقم النظام (`PUR-000001`)
  2. الحالة (شارة)
  3. اسم المورد
  4. مرجع فاتورة المورد
  5. تاريخ الفاتورة
  6. الإجمالي (EGP)
  7. تاريخ الإنشاء
  8. الملاحظات

  البندان ١–٢ في العنوان؛ البنود ٣–٧ في قسم المعلومات بهذا الترتيب؛ البند ٨ (الملاحظات) في قسمه أسفلها.
- **الملاحظات الفارغة (معيار معتمد 2026-07-17):** حين تكون الملاحظات فارغة أو غير موجودة يُعرض **دائمًا**
  النص القياسي: «لا توجد ملاحظات».
- **مرجع فاتورة المورد:** يُعرض حين يوجد؛ حين يغيب يظهر «—» (تحسين اتساق مستقبلي — TD-109: عدم إظهار حقل فارغ).
- **الحالات الأربع للعرض (نمط تفاصيل المنتج):**
  - **تحميل** → مؤشّر تحميل.
  - **بيانات** → بطاقات الترويسة بالترتيب القانوني أعلاه.
  - **غير موجود** → حالة «غير موجود» واضحة (لا خطأ عام): «فاتورة الشراء غير موجودة».
  - **خطأ** → رسالة خطأ مع إعادة المحاولة.
- **الفتح من القائمة (لا مسارات فتح أخرى):** نقر صف الجدول · مفتاح **Enter** على الصف · نقر بطاقة الجوال.
- **الاستجابة:** تخطيط متجاوب دون فيض أفقي على سطح المكتب والجوال؛ RTL؛ خصائص CSS منطقية فقط.
- **لا إجراءات:** لا زرّ تحرير/استلام/إلغاء في هذه الشريحة (عرض فقط).
- **المسارات (قرار توجيه مقصود — لا تغيير كود):** واجهة الـ API `/api/v1/purchase-invoices/{id}` ومسار
  الواجهة `/purchases/:id`. *The frontend route is optimized for user navigation while the backend
  follows resource-oriented API naming.*
